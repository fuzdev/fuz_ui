link_type_json_terminals(tokens: TypeJsonToken[], resolves: (name: string) => boolean): TypeJsonToken[]

Splits each terminal code token of a rendered TypeJson tree at the names to_type_text_tokens finds, so the names inside terminal text (typeof A, { a: A; }, (a: A) => B) link as the same text rendered flat does. text tokens (punctuation, tuple labels) and name tokens pass through unscanned. A split name carries no module, so it resolves by name, as a flat string's names do.

import {link_type_json_terminals} from '@fuzdev/fuz_ui/type_link.ts';

to_type_text_tokens

type_link.ts view source

to_type_text_tokens(type: string, resolves: (name: string) => boolean): TypeTextToken[]

Splits a flat type string into the names that resolve and the text around them, for type text svelte-docinfo emits with no structure: a flat string with no tree beside it, and a tree's terminal text (object and function types, and source text such as typeof a or keyof A). (a: A) => B can then link A and B independently.

The scan is lexical, not a parse. It skips what plainly isn't a type reference: TypeScript's keywords, string and template literals whole (so a template's ${A} doesn't link), comments, a property access's right side (ns.Name: a dotted chain links its head, or, when the head resolves nowhere, its last name, so typeof specs.a_spec over a namespace import links a_spec), and a property or parameter name (name: and name?:, written with no space before the colon, unlike a conditional type's ? A : B). A name in another non-type position (a method key, a binding name, a type parameter) still links when a declaration happens to share it.

import {to_type_text_tokens} from '@fuzdev/fuz_ui/type_link.ts';

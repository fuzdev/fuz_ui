media_devices.svelte.ts

The browser's media devices, its mic and camera permissions, and the devices a person picked, as reactive state.

Browsers hide device ids and labels until a permission is granted: before that, enumerateDevices lists blank entries (Chromium, Firefox) or none (Safari). So a picked device is a *preference*, kept while its device is away (unplugged headphones come back as the pick), and to_device_constraint asks for it as hard as the list can vouch for it. Storing the picks is the consumer's: seed them with initial_selection and save them from on_select.

Re-reads the devices and the permissions.

listen
(): () => void
#

Refreshes now and follows changes (devicechange, permission change) until the returned stop, for an $effect or onMount. A granted permission reveals labels, so the devices are re-read with it. Several components may listen at once: permissions are followed until the last one stops, and each stop counts once.

The listed device picked for kind, or null for the default or a device that's away.

labeled_for
(kind: MediaDeviceKind): boolean
#

Whether the list carries real ids and labels for kind. A browser that has the mic's permission but not the camera's labels the audio devices and leaves the cameras blank, so each kind is vouched for on its own.

missing
(kind: MediaDeviceKind): boolean
#

Whether the pick for kind is known to be away: a device was picked, the list is labeled for kind, and the device isn't in it. The pick is kept, so the device is used again when it returns.

to_device_constraint
(kind: "audioinput" | "videoinput"): ConstrainDOMString | undefined
#

The deviceId constraint for the pick of kind: exact when the list vouches for it, ideal while the list can't be checked for kind (before its permission), and undefined for the default or a device that's away, so opening it never fails on a stale pick.

feat: head API docs fields with their TypeScript signatures — `DeclarationDetail` renders each member, prop, and parameter under its signature (`readonly name?: Type = default`, `name(a: A): R`), composed from the structured data so every type links, and composes a function's, snippet's, and overload's own signature the same way; a signature whose extraction failed keeps its flat form. The `type`, `optional`, and repeated `returns` rows are gone, a parameter gets a row only when it has a description, default, or documented properties (now rendered), and the field groups are labeled (`parameters`, `props`, `members`). The description comes before the import statement, members before examples, and a signature that only repeats the declaration's name is dropped. Each rendered field (members, props, CSS custom properties, parameters with a row) has a `Declaration.field` id and a hashlink, `@throws` types render through `TypeLink`, and `Hashlink` shows on keyboard focus. `TypeLink` links the declaration names inside a flat object or function type (`(a: A) => B`, `{ a: A; }`), keeping the syntax highlighting, and never links a TypeScript keyword such as `string` to a declaration of that name. New `declaration_detail.ts` and `type_link.ts` hold the pure helpers.

breaking: the `hash` of `DeclarationLink` (and of `DocsLink` and `TypeLink`, which forward it) replaces the declaration's own fragment instead of appending a second one (`#Name#hash`), so a field is `hash="Name.field"`; `ApiDeclarationList` no longer sets `id` on each declaration's `article` (the section header's hashlink already carries it); `DeclarationDetail`'s field names are `h5` (a field's own parameters `h6`), not `h4`
